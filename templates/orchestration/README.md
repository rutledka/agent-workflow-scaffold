# orchestration/ — the work graph as data

This directory is the machine-readable half of the agent workflow. The persona files in
`agents/` describe *how* each role works; this directory declares *what the loop operates
on* — so that the frontier, blockers, resource limits, and quality gates are **computed,
not re-derived by an LLM reading prose every run**.

| File | Nature | Edited by |
|---|---|---|
| `graph.yaml` | **Policy** — personas, file domains, resources, gates, budgets, weights | Humans, via PR. Changes rarely. |
| `state.json` | **Derived** — tickets, blockers, computed frontier, scores, hold reasons, invariant results | `scripts/graph-sync.sh`, every cycle. **Never hand-edit.** |
| `schemas/dispatch-result.json` | Contract for headless sub-agent output (`claude -p … --json-schema`) | Humans, via PR |
| `schemas/qa-verdict.json` | Contract for the QA gate's verdict artifact | Humans, via PR |
| `.runtime/` | Lockfiles, preflight failure counter, checkpoints. **Gitignored.** | Scripts only |

## The ownership boundary (read this twice)

- **The PM tool owns ticket status.** `state.json` is a regenerated cache of it. If they
  disagree, the PM tool is right and the cache is stale — rerun `graph-sync`.
- **`graph.yaml` owns ownership and policy.** If a PM-tool label disagrees with
  `graph.yaml`'s persona map, the label is wrong — `graph-sync` flags it as an invariant
  failure and the label gets corrected.
- Neither direction is bidirectional sync. Bidirectional sync is the thing that always
  rots.

## Generated views

`graph-sync` renders human-readable views from `state.json`:

- `pm/delivery-status.md` (PM-tool projects only) — epic index + milestone roll-up,
  headed `<!-- GENERATED BY graph-sync — DO NOT EDIT -->`.
- Any file section between `<!-- GENERATED FROM orchestration/graph.yaml -->` and
  `<!-- /GENERATED -->` markers (the orchestrator role map, the README persona table)
  is rewritten in place from the single declaration here.

Because a row appears in a generated view *because the source object exists*, an epic
that exists in the PM tool can no longer silently be missing from the index — the
failure class is impossible by construction, not caught by periodic reconciliation.

## Why this exists

Field experience running the scaffold's orchestrator on a schedule: eight consecutive
degraded runs each wrote an excellent forensic report and did zero work (no guard on the
loop); delivery status in a hand-maintained file rotted for eight weeks after being
flagged; a capacity-1 shared database was "enforced" by two sessions reading the same
paragraph. Every failure was scaffolding, not model quality. The fix is the same
discipline a graph runtime gives you — typed state, guard edges, bounded budgets,
machine-readable traces — without adopting a graph framework for an eight-node loop.

The governing rule, from the source design: **a gate is a command with an exit code, or
it is not a gate.**
